### 2. Settlement Formula (§3.3)

```text
intendedUserSettlement = Σ providerCostMicroIdr
                          from policy-eligible contributing attempts

actualUserSettlement = min(intendedUserSettlement, reservedMicroIdr)

release = reservedMicroIdr - actualUserSettlement
systemSubsidy = max(eligibleActualCost - actualUserSettlement, 0)
```

**Interpretation:** User never charged more than confirmed reservation cap; excess absorbed as system liability (overage incident evidence). PM decision #2 selects "durably contributing winner only" eligibility; PM decision #3 approves this formula without markup/product-price adjustments in W3.3.

### 3. User Charge Cap & Overage Policy (§3.3, §14)

- User charge strictly capped at `reservedMicroIdr` (PM decision #4).
- Overage (`eligibleActualCost > reservedMicroIdr`) → system-funded incident evidence via `incident:credit-overage:{reservationId}:{allocationId}`.
- Never negative user balance; never silent overcharge.

### 10. Reservation State Machine & Financial Shape Rules (§4.2, §4.3)

Amount invariant: `R > 0`, `S >= 0`, `L >= 0`, `E >= 0`, `S + L + E = R` (DB-enforced via CHECKs).

| Status | Financial Shape | Meaning | `closingAt` |
|--------|-----------------|---------|-------------|
| `open` | `S=0, L=0, E=R`, `closingAt=null` | Job active/queued; entire hold unresolved | NULL |
| `closing` | `E>0, closingAt!=null` | Terminal but unresolved attempts remain held | NOT NULL |
| `settled` | `S>0, E=0, S+L=R, closingAt!=null` | Usable output with positive user settlement | NOT NULL |
| `released` | `S=0, L=R, E=0, closingAt!=null` | Zero-charge outcome (user-paid S=0 OR system-funded) | NOT NULL |
| `cancelled` | `S=0, L=R, E=0, closingAt!=null` | Cancellation outcome | NOT NULL |
| `expired` | `S=0, L=R, E=0, closingAt!=null` | Reservation expired before usable execution | NOT NULL |

**Derived Tuple Rule (PM decision #14):** Status derived strictly from computed `(S, L, E)` tuple:
- `closing` written IFF `E_target > 0` (DB CHECK requires exposure > 0)
- When `E_target = 0` (e.g., user settlement reaches reservation cap `S = R`), reservation transitions directly to `settled` (if `S > 0`) or `released` (if `S = 0`), even if attempts remain unresolved
- Any transition out of `open` sets `closingAt = COALESCE(closingAt, NOW())`

floor = amount / unit;                                // bookBalance / availableCredits (truncate toward zero)
